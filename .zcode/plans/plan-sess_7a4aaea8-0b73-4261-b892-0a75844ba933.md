# GameSpace 번인가드 Magisk 모듈 — 구현 계획

## Context

목표: crDroid GameSpace 소스를 기반으로 **OLED 번인 방지 + 방치형 절전 모드**(① Galaxy식 검은 오버레이 잠금, ② Xiaomi식 루트 백라이트 소등)를 추가한 `GameSpace.apk`를 단독 Gradle로 빌드하고, 시스템 앱 오버레이용 **Magisk/KernelSU 플래시 가능 .zip**을 산출하는 독립 레포를 구축한다.

조사로 확인된 전제:
- 워크스페이스는 LICENSE(Apache-2.0)만 있는 백지. JDK 21, Android SDK(`C:\Users\Luna\android-sdk`, android-35/build-tools 34·35, 라이선스 승인됨), adb(platform-tools), 7-Zip(`C:\Program Files\7-Zip\7z.exe`) 사용 가능. `zip` 바이너리는 없음.
- 상류는 crDroid 세대별 브랜치(`12.1`~`17.0`)를 운영하며 **이미 Gradle 스캐폴딩 + platform.jks(AOSP testkey)를 포함**하나, `system_libs/*.jar`(숨은 API/벤더드 라이브러리 스텁)가 git에 없다. 최신 `17.0`은 AxionOS 플랫폼 후킹(AxPlatformClient, ax_compose, SceneTransitionLayout)에 의존한다.
- 매니페스트에 `sharedUserId="android.uid.system"` 존재, INJECT_EVENTS/MONITOR_INPUT/WRITE_SECURE_SETTINGS 등 signature 권한 다수 → **AOSP 공개 testkey 서명**(사용자 확정)으로 유지. 백라이트/cpufreq/주사율 제어는 지시문대로 `su` 경유.

## Phase 0 — 브랜치 확정 (adb 프로브)

plan 모드에서 실행 못 한 adb 조사를 구현 첫 단계로 수행:
- `pm path io.chaldeaprjkt.gamespace`, `dumpsys package io.chaldeaprjkt.gamespace`(설치된 versionName/versionCode → 대응 상류 브랜치 선택: 구세대 기기일수록 Ax 의존이 없는 과거 브랜치 사용), API 레벨, `/sys/class/backlight/`, `/sys/class/devfreq/`, `/sys/class/kgsl/`, Magisk 유무(`su -V`, which magisk).
- 기기 미연결 시 폴백: 기기에 설치된 GameSpace versionName으로 브랜치 추정, 실패 시 `16.0-qpr1` 기준 + 런타임 동적 탐색.
- 참고: 백라이트/devfreq 노드가 아예 없는 기기라면 모드 2는 자동 폴백(모드 1)하므로 브랜치 결정이 곧 빌드 타겟이 됨. compileSdk 36이 필요하면 `sdkmanager "platforms;android-36"` 추가 설치(라이선스 이미 수용됨).

## Phase 1 — 레포 스캐폴딩 + Gradle 컴파일 그린

지시문의目录 구조를 따르되, 상류가 이미 제공하는 Gradle 파일을 기반으로 삼는다(재작성 아님, 채워 넣기):

```
gamespace-burnin-guard-magisk/
├── app/                  # 상류 선택 브랜치의 app/ (res, java, AndroidManifest, platform.jks, proguard)
├── stubs/                # 지시문의 libs/ 역할: compileOnly 숨은 API 스텁 + 벤더드 클래스의 최소 실제 구현
├── magisk-module/        # module.prop, customize.sh, system_ext/
├── .github/workflows/build.yml
├── build.sh, LICENSE, NOTICE, README.md, .gitattributes
```

주요 작업:
1. 선택 브랜치 shallow clone → `app/`로 이식(상류의 settings.gradle.kts/gradle.properties/gradlew 포함, `app/src/main/Android.bp`는 참조 문서로 보존).
2. **stubs 모듈** 작성 (`compileOnly` + 런타임에 필요한 것은 실제 구현):
   - 숨은 API 컴파일 스텁(android.jar 동일 패키지명): `Settings.*ForUser`, `ServiceManager`, `SystemProperties`, `ActivityTaskManager.getService()`, `IDeviceIdleController`(AIDL), `TaskFpsCallback`+`WindowManager.registerTaskFpsCallback`, `InputManager.monitorGestureInput`/`InputMonitor`/`InputEventReceiver`, `ScreenshotHelper`/`takeScreenshot`, `AudioSystem` — 파일별 사용 지점은 조사 리포트대로.
   - 런타임 실제 구현(경량 shim, 업스트림이 static_libs로 패키징하던 것의 대체): SettingsLib의 사용 클래스 3종(`CollapsingToolbarBaseActivity` → Toolbar 기반 Activity, `SettingsBasePreferenceFragment` → PreferenceFragmentCompat, `IllustrationPreference` → LayoutPreference로 대체), `lineageos.preference`의 crDroid 커스텀 Preference 클래스군(crDroid 기기에서는 LineageSettings provider가 프레임워크에 존재하므로 프로바이더 스텁만).
   - AxionOS 계열 브랜치를 고를 경우: `AxPlatformClient`/`ax_compose`/SceneTransitionLayout은 no-op 스텁 + try/catch 가드로 처리(해당 타일만 기능 저하), GameBarScenes가 SceneTransitionLayout을 쓰면 기존 AnimationVisibility로 소폭 리팩터(포팅 시 결정, 리스크 항목).
3. 매니페스트 수정: `android:sharedUserId` 제거(지시문), `versionCode 999999`, 서명은 상류 `app/platform.jks`(AOSP testkey) 재사용. `android:persistent` 유지.
4. **컴파일 그린까지 Phase 1 완료 기준** — `./gradlew assembleRelease` 성공 후 다음 단계.

## Phase 2 — 신규 기능 (패키지 `io.chaldeaprjkt.gamespace.burnin`)

기존 인프라 재사용 중심:
- **설정 UI**: 기존 `xml/root_preferences.xml`에 PreferenceCategory 추가(crDroid `SystemSettingSwitchPreference`/`CustomSeekBarPreference` 위젰 재사용 → 상류 코드 스타일 그대로). 항목: 모드 선택(없음/모드1/모드2), 오버레이 불투명도(80–100%), 자동 진입 타이머(사용안함/1·3·5분), CPU/GPU 클럭 상한 비율(기본 50%), 주사율 60Hz 고정 토글, (안심용) 최대 잠금 후 자동 복원 시간.
- **RootShell**: `Runtime.exec("su -c …")` 단일 executor + 타임아웃 + 성공/실패 결과 타입. 모드 2·클럭·주사율 전용.
- **BacklightController**: `/sys/class/backlight/*/brightness` glob 탐색, 기존값·max_brightness 캐싱, su로 쓰기, 복원. 쓰기 실패 시 모드 1 폴백.
- **ClockLimiter**: `cpu*/cpufreq/scaling_max_freq` 원값 백업 후 비율 적용, GPU는 `/sys/class/devfreq/*/max_freq`(없으면 kgsl pwrlevel) 탐색.
- **RefreshRateLimiter**: `su settings put system min_refresh_rate/peak_refresh_rate 60` + 복원. (상류의 기존 refresh-rate lock 타일 코드 확인 후 재사용 가능분 재사용)
- **BurnInGuardService** (SessionService가 게임 세션 중 띄우는 Foreground Service):
  - 모드 1: `TYPE_APPLICATION_OVERLAY` ComposeView — 설정 불투명도 검은 스크림, 중앙 잠금 아이콘+시계+배터리, 60초마다 위치 지터, `FLAG_KEEP_SCREEN_ON`, Window focusable로置いて 볼륨키(더블클릭/길게누르기)로 해제, 잠금 아이콘 드래그-아웃으로 해제.
  - 모드 2: 백라이트 0 + 터치차단 오버레이(5연속 탭 볼륨키로 복원). 소등 중 터치차단창이 킷 이벤트를 받으므로 동일 트리거.
  - 안전장치: 서비스 데드맨 워치독(자동 복원시간 초과 시 복원), 크래시 후 재시작 시 백라이트/클럭/주사율 무조건 복원, 오버레이 실패 시에도 백라이트는 su로 직접 복원 가능함을 README에 명시.
- **진입 트리거**: ① 사이드 패널 타일 — `TileRepository`에 로컬 타일 `[화면 보호/소등]` 추가(기존 "stay awake" 타일과 동일한 로컬 타일 패턴). ② 유휴 타이머 — 상류 `KeyInputMonitor`(monitorGestureInput)이 있으면 그 이벤트 스트림에 리스너를 붙이고, 없으면 임의 뷰의 ViewTreeObserver touch feed로 구현(구세대 브랜치 선택 시 후자).

## Phase 3 — Magisk 모듈 · build.sh · CI

- `magisk-module/`: `module.prop`(id `gamespace_burnin_guard`, KernelSU 호환 minMagisk 버전), `customize.sh`(LF·0755), 스테이징된 `system_ext/` + 폴백용 `system/` 트리를 설치 중 감지된 파티션으로 재배치 — 감지 순서: `pm path io.chaldeaprjkt.gamespace` → `/system_ext/priv-app/GameSpace` 존재 확인 → `system/priv-app` 폴백. 상류 `privapp_whitelist_….xml`을 기준으로 신규 권한 반영한 `etc/permissions/privapp-permissions-io.chaldeaprjkt.gamespace.xml` 동봉.
- `build.sh`(bash, Git Bash 동작): gradlew assembleRelease → `magisk-module`에 APK 복사 → `"C:/Program Files/7-Zip/7z.exe" a -tzip`으로 `dist/GameSpace-BurnInGuard-v<ver>.zip`(LF 강제는 `.gitattributes`에 `*.sh text eol=lf`). Magisk는 부팅 시 스크립트를 sh로 실행하므로 exec 비트 의존 없음.
- `.github/workflows/build.yml`: tag(v*) 트리거 → setup-java 21 → `android-actions/setup-android`(platforms;android-35/36, build-tools) → `gradlew assembleRelease` → 모듈 zip 조립 → gh release 업로드.
- README: 빌드/플래시 법, **부트루프·소등 안전 복구**(모듈 자동 비활성화 설명, `adb shell "su -c 'echo <원값> > /sys/class/backlight/…/brightness'"`, 매직 `disable` 파일 생성법), Apache-2.0 유지 + `NOTICE`(chaldeaprjkt/crdroidandroid/AxionOS 저작 표기 + 수정 내역).

## 구현 순서와 검증

1. **Phase 0–1**: adb 프로브 → 브랜치 확정 → `./gradlew assembleRelease` 성공(로컬 SDK, JDK 21). 검증: 빌드 산출물에 platform.jks 서명(`apksigner verify`), `aapt dump badging`으로 package/sharedUserId/versionCode 확인.
2. **Phase 2**: 컴파일 그린 상태에서 burnin 패키지·설정 UI·타일 추가, 재빌드.
3. **Phase 3**: build.sh로 zip 산출, `unzip -l` 구조 확인(LF/경로).
4. **기기 E2E**: `adb push zip` + `su -c 'magisk --install-module <zip>'` → 재부팅 → `pm path`(모듈 경로로 마운트되는지)·서명/권한(`dumpsys package` granted 확인) → 게임 실행 → 패널 타일로 모드 1/2 진입 → 볼륨키·5탭 해제 → 원복 확인(`cat` 백라이트/cpufreq, `settings get system min_refresh_rate`) → 유휴 타이머 자동 진입 → 모드 2 노드 없는 경우 폴백 동작.
5. **CI**: 태그 푸시로 release 산출물 생성 확인.

## 리스크/주의

- **브랜치-ROM 불일치**: GameSpace는 롬 프레임워크(game_start 전송, LineageSettings 등)와 짝이 맞아야 하므로 Phase 0의 버전 매칭이 가장 중요. 최신 17.0 계열은 Ax 후킹으로 일부 타일이 저하 동작(스텁 가드로 크래시는 방지).
- SceneTransitionLayout 의존이 깊으면 GameBarScenes 소폭 리팩터로 대체(포팅 대신).
- 백라이트 0 방치 방지를 위해 자동 복원 시간 기본값(예: 10분)을 켜둔 채 출시.
- 상류 30개 로케일 strings는 그대로 병합, 신규 문자열은 values(영)+values-ko만 추가.
